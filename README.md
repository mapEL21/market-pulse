# Market Pulse

Инструмент отбора криптовалютных фьючерсов для ручного анализа.

Из нескольких сотен инструментов на Binance и OKX отбирает те, которые
**ведут себя необычно относительно своего собственного обычного состояния**,
и объясняет, по каким признакам каждый из них попал в список.

> Это не торговый бот. Система не даёт сигналов на покупку и не предсказывает
> цену. Её задача — сократить список инструментов, которые стоит открыть
> и посмотреть глазами.

**Статус:** в разработке. Реализованные этапы отмечены ниже.

---

## Зачем

При ручном поиске точек интереса трейдер пролистывает сотни графиков подряд.
Большинство инструментов неликвидны или неактивны, и основное время уходит
не на анализ, а на поиск того, что вообще достойно анализа.

Market Pulse автоматизирует именно этот отсев.

---

## Как это работает

```
Список инструментов  →  Фильтры  →  Метрики  →  Скоринг  →  Отчёт
      527 шт             39 шт      RVOL       ранжирование   топ-15
                                    RTC                       + объяснение
                                    VE
```

Три метрики, каждая сравнивает последнюю закрытую свечу с обычным поведением
инструмента за предыдущие 48 часов (медиана, не среднее):

| Метрика | Что показывает |
|---|---|
| **RVOL** | во сколько раз объём выше обычного |
| **RTC** | во сколько раз больше сделок, чем обычно |
| **VE** | во сколько раз шире диапазон свечи |

Кандидатом становится инструмент, у которого сработало **не меньше двух метрик
из трёх** — защита от разовой аномалии в одном показателе.

Точные формулы, окна и пороги — в [docs/spec.md](docs/spec.md).

### Пример вывода

Настоящий прогон, свеча 15m:

```
Market Pulse — свеча 15m, закрытие 2026-08-12 23:00 UTC
База сравнения: 192 свечи (48 ч), медиана

Отсев:
  статус торгов не TRADING        0
  оборот < 50.0M USDT           488
  сделок < 10 000                 0
Загрузка свечей: 39 инструментов за 21 с (скачано 39, из кэша 0)
Отсев по короткой истории: 0

BINANCE USDT-M perp   проверено 527 → после фильтров 39 → кандидатов 5

──────────────────────────────────────────────────────────────────────
 1. APRUSDT · PERP          score 3.00
──────────────────────────────────────────────────────────────────────
    Изменение за свечу:  +6.46 %
    Оборот за 24 ч:      851.0M USDT

    Почему в списке:
    • Объём свечи 21.0M USDT — в 793.3× выше обычного
      (обычно 26.5K USDT за свечу)
    • Сделок 223 538 — в 459.5× больше обычного
      (обычно 486 за свечу)
    • Диапазон свечи 11.0 % — в 12.5× шире обычного
      (обычно 0.9 %)

    Итог: Все три метрики выше порога — инструмент вышел из своего обычного
    режима. Средняя сделка в 1.7× крупнее обычной.
```

Пользователь всегда видит и коэффициент, и абсолютные числа, из которых он
получен. Непрозрачный «score 2.31» без обоснования — сознательно исключён.

Если метрика до порога не дотянула, она показывается отдельным блоком
«Не сработало» вместе со своим порогом: то, что диапазон свечи остался
прежним при выросшем объёме, — тоже содержательная информация.

## Установка

```bash
git clone https://github.com/mapEL21/market-pulse.git
cd market-pulse

python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
```

Ключи API не нужны — используются только публичные эндпоинты бирж.

## Запуск

Основной прогон — отбор кандидатов на последней закрытой свече:

```bash
python -m src.main
```

Заполнить результаты кандидатов, которым уже больше восьми часов:

```bash
python -m src.outcomes
```

Проиграть прошедшую неделю как 672 прогона на биржу и сразу заполнить
результаты — так база наполняется за минуты вместо месяцев:

```bash
python -m src.backtest
```

SQL-анализ накопленного, каждый раздел печатает свой запрос:

```bash
python -m src.analysis
```

Собрать страницу `data/report.html` и открыть её в браузере:

```bash
python -m src.report_html
```

Страница статическая: ни сервера, ни внешних файлов, работает офлайн.
Данные обновляет прогон, страница только показывает — поэтому кнопки
«Обновить» на ней нет, и это осознанно: полный прогон занимает десятки
секунд, и кнопка, вешающая страницу на это время, была бы хуже, чем
её отсутствие.

## Что показал анализ

Неделя истории, проигранная бэктестом: **1344 прогона, 30 695 наблюдений**
по двум биржам, у каждого заполнено, что случилось с ценой после.
Запросы и полный вывод — `python -m src.analysis`.

### Отбор работает

| Группа | Наблюдений | Средний ход за 2 ч | Доля ходов ≥ 3 % |
|---|---|---|---|
| Кандидаты | 3 710 | **5.40 %** | **42.4 %** |
| Остальные | 26 985 | 2.38 % | 20.2 % |

Инструменты из списка ходят в 2.3 раза сильнее тех, что в список не попали,
и заметное движение у них случается вдвое чаще.

**Но это не открытие, а подтверждение.** Волатильность кластеризуется:
инструмент, который сильно двигался только что, с большой вероятностью
продолжит двигаться и дальше — это известное свойство рынков. Ценность
инструмента не в том, что он обнаружил этот эффект, а в том, что он находит
такие инструменты за 20 секунд вместо часа листания графиков.

### Сигнал усиливается монотонно

| RVOL | Наблюдений | Средний ход за 2 ч | Доля ходов ≥ 3 % |
|---|---|---|---|
| до 1× | 15 058 | 2.12 % | 18.3 % |
| 1–2× | 8 156 | 2.56 % | 21.4 % |
| 2–3× | 3 006 | 3.16 % | 26.2 % |
| 3–5× | 2 145 | 3.59 % | 29.9 % |
| 5–10× | 1 310 | 4.99 % | 35.6 % |
| 10×+ | 1 020 | **7.41 %** | **62.6 %** |

Зависимость есть и она монотонная — метрика измеряет то, что задумано.

**Порог 3.0 оказался мягким.** Между «2–3×» и «3–5×» разница невелика
(26 % против 30 %), а настоящий разрыв начинается с 5×, и особенно с 10×.
Это первый кандидат на изменение по результатам данных, а не по ощущению.

### Правило «не меньше двух метрик» оправдалось

| Сработало метрик | Наблюдений | Средний ход за 2 ч | Доля ходов ≥ 3 % |
|---|---|---|---|
| 0 | 24 752 | 2.28 % | 19.5 % |
| 1 | 2 176 | 3.44 % | 29.2 % |
| 2 | 2 342 | 4.19 % | 35.2 % |
| 3 | 1 425 | **7.27 %** | **53.2 %** |

Каждая дополнительная сработавшая метрика улучшает результат. Требование трёх
из трёх дало бы заметно более чистый список ценой втрое меньшего числа
кандидатов.

### Треть кандидатов — пустышки

У 27.6 % кандидатов Binance и 33.7 % кандидатов OKX за два часа цена
не сдвинулась даже на 1 %. Это честная цена метода, и её стоит знать заранее.

### Спор про 50 против 200 млн решён в пользу 50

| Оборот за 24 ч | Кандидатов | Средний ход | Доля ходов ≥ 3 % |
|---|---|---|---|
| 50–100M | 1 086 | 5.25 % | **48.3 %** |
| 100–200M | 979 | 5.17 % | 46.1 % |
| 200M+ | 1 645 | 5.63 % | 36.2 % |

У крупных инструментов средний ход чуть выше — его вытягивают отдельные
сильные движения, — но **заметное движение случается у них заметно реже**.
Порог 200 млн отсёк бы самую результативную часть списка.

### Две метрики хуже трёх

| Биржа | Кандидатов | Средний score | Средний ход | Доля ходов ≥ 3 % |
|---|---|---|---|---|
| Binance (3 метрики) | 2 150 | 1.83 | **6.92 %** | **51.2 %** |
| OKX (2 метрики) | 1 560 | 2.00 | 3.30 % | 30.2 % |

Показательное сравнение: у OKX **средний score выше**, а результат вдвое
хуже. Причина в том, что RVOL и VE сильнее связаны между собой, чем каждая
из них с числом сделок: правило «обе из двух» отсеивает слабее, чем «две
из трёх». Отсутствие числа сделок в API OKX стоит дороже, чем казалось.

### Час суток важнее, чем ожидалось

Лучшие часы по среднему ходу кандидатов — **05:00–07:00 UTC** (10.2–10.7 %),
то есть начало азиатской сессии. Худшие — вдвое слабее. Вопрос, отложенный
на этапе 4, получил ответ: время запуска влияет на качество списка сильно.

### Чего эти числа не доказывают

- **Одна неделя и один режим рынка.** Выводы могут не пережить смену фазы.
- **Выживший отбор.** Список инструментов брался сегодняшний; делистнутые
  за неделю в выборку не попали, а это часто как раз те, кто сильно двигался.
- **Порог «заметного движения» в 3 %** выбран для наглядности, а не выведен
  из чего-то.
- **Движение — не прибыль.** Ход на 5 % в любую сторону не означает, что
  на нём можно было заработать: направление система не предсказывает.

## Исследовательская часть

Каждый прогон сохраняется в базу вместе с тем, что происходило с ценой
инструмента **после** попадания в список. Это превращает инструмент
в проверяемую гипотезу и позволяет отвечать SQL-запросами на вопросы:

- при каких значениях метрик чаще случались сильные движения;
- какие пороги дают больше всего ложных срабатываний;
- отличается ли поведение кандидатов на разных биржах.

Пороги и веса в скоринге — стартовая гипотеза, а не подобранные константы.
Их проверка на накопленных данных — отдельный этап проекта.
