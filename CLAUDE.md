## 1. Что это за проект

**Market Pulse** — аналитический инструмент для крипторынка.

Задача: автоматически просмотреть сотни фьючерсных инструментов и выдать
трейдеру **короткий список кандидатов, которые стоит открыть и изучить вручную**,
с объяснением, почему каждый попал в список.

Это **не** торговый бот и **не** система поиска точек входа.
Финальное решение всегда принимает человек.

## 2. Кто автор проекта и как со мной работать

Автор — студент 4 курса, база в Python, SQL изучается сейчас, опыта больших
проектов нет. Проект одновременно учебный, портфолийный и практический.

**Главное правило:**

> Если я не понимаю решение — оно не должно появляться в проекте.

Из этого следует, как надо себя вести:

1. **Сначала план, потом код.** На любую задачу сначала выдай план:
   что будет сделано, в каких файлах, какие решения приняты и почему,
   какие были альтернативы. Жди подтверждения перед реализацией.
2. **Маленькие шаги.** Один шаг = одна функция или один небольшой модуль,
   который можно запустить и проверить. Не пиши сразу несколько модулей.
3. **Объясняй после написания.** После каждого куска кода — краткое
   объяснение простыми словами: что делает, зачем именно так, что было бы
   альтернативой.
4. **Не добавляй ничего сверх задачи.** Никаких «заодно я тут ещё сделал».
   Если видишь, что нужно что-то ещё — предложи отдельным пунктом.
5. **Спрашивай, если неоднозначно.** Лучше уточняющий вопрос,
   чем догадка и лишний код.
6. **Простое решение лучше умного.** Если можно обойтись стандартной
   библиотекой или простой функцией вместо абстракции — так и делай.
7. **Не молчаливые компромиссы.** Если приходится упростить или что-то
   не работает — скажи прямо, не заглушай ошибку.

## 3. Границы MVP

### Входит в v1

- Источники: **Binance USDⓈ-M Futures**, **OKX Perpetual Swaps** (только USDT-пары)
- Таймфрейм анализа: **15m** (5m — опцией), база сравнения — 48 часов
- Публичные REST API, без ключей и авторизации
- Фильтрация неликвидных и «мёртвых» инструментов
- Три метрики активности (см. `docs/spec.md`)
- Ранжирование и вывод топ-N кандидатов с объяснением
- Сохранение прогонов в SQLite для последующего анализа
- CLI-интерфейс (запуск командой, вывод в консоль)

### НЕ входит в v1

- ❌ Автоматическая торговля, ордера, любой доступ к аккаунту
- ❌ Поиск точек входа, стоп-лоссов, целей
- ❌ Прогнозирование цены
- ❌ Машинное обучение, нейросети
- ❌ Стакан (order book), WebSocket, реалтайм
- ❌ Веб-интерфейс, дашборды, графики
- ❌ Volume Profile (кандидат на v2)
- ❌ Поддержка других бирж

**Если предлагаешь что-то из этого списка — сначала явно спроси.**

## 4. Технический контекст

- Python 3.14, venv в `.venv`
- ОС: Windows, редактор VS Code
- Git + GitHub, коммит после каждого завершённого шага
- Зависимости минимальные: `requests`, `pytest`. Всё остальное — стандартная
  библиотека (`statistics` для медианы, `sqlite3` для базы, `datetime`, `json`).
  Новую библиотеку — только с обоснованием и вопросом.
  pandas намеренно не используется: данных мало, структура плоская,
  а сборка под Python 3.14 требует компилятора C++.
- БД: SQLite (стандартный модуль `sqlite3`, без ORM — SQL пишется руками,
  это часть учебной цели)

## 7. Определения метрик

Все метрики определены математически однозначно в `docs/spec.md`.
**Не используй в коде расплывчатые формулировки** вида «объём выше среднего».
Любая метрика = конкретная формула, конкретное окно, конкретный тип усреднения.
Если формулы для чего-то нет — сначала обсуди и зафиксируй её в spec.md.
